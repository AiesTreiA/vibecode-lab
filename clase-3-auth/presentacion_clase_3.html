ARQUITECTURA DE DATOS

El Puente de Autenticación: auth.users ➔ public.profiles

Por qué nunca debes mezclar las credenciales protegidas con los datos de tu aplicación.

🔒 auth.users (Esquema Protegido)

Esquema interno gestionado por Supabase. Almacena contraseñas hasheadas (bcrypt), tokens de sesión y correos confirmados.

-- Inaccesible directamente desde el cliente SELECT * FROM auth.users; -- ⚠️ Protegido por roles del sistema
🌐 public.profiles (Tu Base de Datos)

Tu tabla pública vinculada por clave foránea (id = auth.uid()). Guarda roles, avatar, nombres y relaciones de negocio.

CREATE TABLE public.profiles ( id UUID REFERENCES auth.users(id) PRIMARY KEY, email TEXT NOT NULL, full_name TEXT, role TEXT DEFAULT 'user' );
⚡ La Magia del Trigger Automático: Cada vez que un usuario se registra (por correo o Google), Postgres ejecuta una función interna que inserta automáticamente su registro en public.profiles sin depender del frontend.

SEGURIDAD & RLS

Row Level Security (RLS) & Gestión de Claves

El principio de privilegio mínimo: Tu base de datos es el guardia de seguridad definitivo.

1

NEXT_PUBLIC_SUPABASE_ANON_KEY

Pública en el navegador. Sólo es segura porque RLS filtra cada SELECT, INSERT y UPDATE según el usuario logueado.

2

SUPABASE_SERVICE_ROLE_KEY

Clave maestra privada. Salta todas las políticas RLS. NUNCA debe tener prefijo NEXT_PUBLIC_ ni enviarse al cliente.

3

auth.uid() = id

PostgreSQL inyecta el ID del token JWT verificado en cada consulta SQL. Si intentas consultar datos ajenos, Postgres devuelve [].

🛡️ Política RLS en Acción
-- 1. Habilitar seguridad por fila ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY; -- 2. Permitir que cada usuario lea SOLO su fila CREATE POLICY "Ver mi propio perfil" ON public.profiles FOR SELECT USING (auth.uid() = id); -- 3. Permitir editar SOLO su propio perfil CREATE POLICY "Editar mi propio perfil" ON public.profiles FOR UPDATE USING (auth.uid() = id);

RESOLUCIÓN DE ERRORES

🔧 Troubleshooting: Errores Frecuentes en Vivo

Los 3 errores clásicos que le ocurren al 90% de los desarrolladores la primera vez.

🔴 redirect_uri_mismatch

Causa: La URL en Google Cloud no es idéntica a la de Supabase.

Solución: Revisa que no tenga espacios, ni barra final /, y use https://.

🟡 access_denied / No verificada

Causa: La app está en modo Testing y tu correo no está en la lista.

Solución: Añade tu email en OAuth consent screen ➔ Test users.

🔵 Popup se cierra sin sesión

Causa: Falta la ruta de intercambio PKCE /auth/callback.

Solución: Pídele a Antigravity crear app/auth/callback/route.ts con exchangeCodeForSession.
